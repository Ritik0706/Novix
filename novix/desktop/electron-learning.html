1. What is Electron? (Project Overview)

What is Electron?

Electron lets you build desktop applications using web technologies (HTML, CSS, JavaScript). Instead of making a website, you make a real program that runs on your computer - like Photoshop or Word.

Think of it like this

Imagine you have a toy car that looks like a real car but is controlled by a remote. Electron is the "toy car" - it looks like a regular app, but under the hood it's running a website (Chromium browser) with extra powers (Node.js to access your computer).

In Our Project (Novix)

Novix is a local AI chat assistant. Electron wraps a chat interface around a Python backend and an AI model. The Electron parts are:

  • main.js - The boss. Controls everything from the background.
  • preload.js - The messenger. Safely passes messages between the boss and the chat window.
  • package.json - The instruction manual. Tells Electron what to do.
  • chat.js (renderer) - The visible chat window. Talks to the backend.

Two Worlds Inside Electron

Main Process

The "boss". Has full access to your computer. Creates windows, manages files, runs background tasks.

Renderer Process

The "face". This is what you see - the HTML/CSS/JS in the window. Like a web page.

Preload Script

The "messenger". Safely bridges the boss and the face. Only exposes specific safe functions.

3. main.js - The Main Process (Boss of the App)

This is the most important Electron file. The Main Process is the brain. It has access to everything on your computer (file system, network, other programs). It creates windows and manages the app's life.

Think of it like this

The Main Process is the manager of a store. The manager handles money (file system), hires people (spawns Django), locks the doors (app lifecycle), and controls the store layout (creates windows). The customers (users) only see the store window (renderer), but the manager controls everything behind the scenes.

  2. await startDjango() - Download model if needed, copy database, start Django backend.

If anything fails: The catch block kills Django, shows an error window, and returns (never creates the main window).

7. IPC Communication (How Parts Talk)

What is IPC?

IPC = Inter-Process Communication. It's how the Main Process and Renderer Process send messages to each other.

Why: The Main Process and Renderer are separate programs running in separate memory. They can't just reach into each other's variables. IPC is like sending letters between two people in different buildings.

IPC in This Project

This project uses ONLY ONE IPC channel: "close-window". That's it!

Complete IPC FlowVisual

  3. PRELOADipcRenderer.send("close-window")
  4. ↓
  5. MAINipcMain.on("close-window", (event) => { win.close() })
Important: Why not use IPC for everything?

In this project, the renderer talks to the Django backend via HTTP requests (fetch calls), NOT via IPC. IPC is only used for the close button because that's the only thing that needs Electron's permission.

IPC = talk to Electron itself (close window, open file dialogs, etc.)

HTTP = talk to the backend server (send messages, get conversations, etc.)

12. Can I Explain This Project Myself?

Click each question to reveal the answer. If you can answer these, you understand the Electron code!

1. What file does Electron run first when the app starts?
main.js - because package.json says "main": "main.js". This is the entry point.
2. What is the Main Process and what can it do?
The Main Process runs main.js. It has full access to the computer - it can read/write files, start other programs, access the network. It creates windows and manages the app lifecycle. Think of it as the "manager" behind the scenes.
3. What is the Renderer Process?
The Renderer Process runs the web page inside the BrowserWindow - in this case, chat.html + chat.js. It's like a regular web browser tab. It cannot access your computer's files or run Node.js commands (because contextIsolation is ON).
4. What does preload.js do?
preload.js runs before the web page loads. It uses contextBridge.exposeInMainWorld() to safely expose window.electronAPI.closeWindow() to the renderer. It's the only bridge between the web page and Electron.
5. How does the user close the app?
User clicks the X button (HTML) → chat.js calls window.electronAPI.closeWindow() → preload sends IPC "close-window" → main.js receives it and calls win.close() → Django is killed and app quits.
6. Why does the app use frame: false?
To remove the default Windows title bar (minimize/maximize/close buttons). The app has its own custom design with a custom close button and dark theme. This makes it look like a modern chat widget, not a generic window.
7. What is IPC and how is it used here?
IPC (Inter-Process Communication) lets the Main Process and Renderer send messages. Here, there's only ONE channel: "close-window". The renderer sends it via preload's ipcRenderer.send(), and the main process listens with ipcMain.on().
8. Why does the app kill djangoProcess in TWO places?
In window-all-closed AND before-quit. Different closing scenarios trigger different events: clicking the X triggers window-all-closed. Right-clicking the taskbar and choosing Quit triggers before-quit. Both need to clean up Django so it doesn't keep running as a zombie.
9. What is contextIsolation: true and why is it important?
It puts a wall between the web page and Node.js. Without it, any script on the page could access your files, run commands, etc. With it ON, only the preload script can bridge the gap. This project is SECURE because it uses contextIsolation.
10. What does app.getPath('userData') return?
A special folder path where the app is allowed to store data. On Windows it's something like C:\Users\you\AppData\Local\novix. The main process uses it to save the AI model and database. It's the "safe zone" for app data.

14. Beginner Glossary

Main Process
The background "manager" of an Electron app. Has full access to the computer. Runs main.js. Only ONE main process per app.
Renderer Process
The "face" of the app - the HTML/CSS/JS running inside a BrowserWindow. Like a web page in a browser. Can have multiple renderer processes (one per window).
Preload Script
A JavaScript file that runs BEFORE the web page loads. Used to safely expose specific Electron/Node.js functions to the renderer via contextBridge.
BrowserWindow
A class that creates a new window. It's like opening a new browser tab, but for your desktop app. Each window runs its own renderer process.
IPC (Inter-Process Communication)
A way for the Main Process and Renderer Process to send messages to each other. They can't share memory, so they use IPC as a messaging system.
ipcMain
The Main Process side of IPC. Listens for messages with ipcMain.on().
ipcRenderer
The Renderer side of IPC. Sends messages with ipcRenderer.send(). Used here only in the preload script.
contextBridge
A security tool that creates a safe bridge between the preload script and the web page. Only exposes what you explicitly allow.
contextIsolation
A security setting. When true, the web page can't access Node.js APIs directly. Only the preload script can bridge the gap.
spawn
A Node.js function to start a new program as a child process. Used here to start the Python backend.
userData
A special folder path (app.getPath('userData')) where the app is allowed to store user data. Safe and persistent.
app.whenReady()
Returns a Promise that resolves when Electron has finished initializing and is ready to create windows.
process.env
An object containing all environment variables. Like a list of settings the operating system provides.
__dirname
The directory (folder) that the current file is in. Used to build paths to other files.
Promise
A JavaScript object that represents something that will happen in the future. await pauses until it finishes.
require()
Node.js function to import a module (a package of code). Like import in browsers but for Node.js.
async/await
A way to write asynchronous code that looks like regular code. async marks a function as asynchronous. await pauses until a Promise finishes.
